# Java Functional Programming: The Complete Guide

A comprehensive reference for Java's functional API, covering lambdas, method references, streams, and advanced patterns.

## **1. The Big Picture**

### **1.1 What is "Functional API"?**

In Java, "Functional API" refers to features that treat behavior (code) as data (values). Instead of writing verbose anonymous inner classes, you pass functions—defined via lambdas or method references—into methods.

```java
// Behavior as data: passing logic as a parameter
void repeat(int n, Runnable task) {
    for (int i = 0; i < n; i++) task.run();
}

repeat(3, () -> System.out.println("Hi")); // prints 3 times

```

### **1.2 Why use it?**

1. **Conciseness:** Removes boilerplate.
2. **Declarative Style:** Focus on _what_ to do, not _how_ (iteration mechanics).
3. **Parallelism:** The JVM can optimize functional pipelines (e.g., `parallelStream`).

## **2. Functional Interfaces: The Core**

### **2.1 Definition & The Annotation**

A **Functional Interface** is an interface with **exactly one abstract method**.

- **`@FunctionalInterface`**: This annotation is optional but recommended. It forces a compiler error if the interface does not satisfy the single-abstract-method rule.
- **Structure:** They may contain default or static methods, but only one abstract method.

### **2.2 The "Big Four" Interfaces**

| Interface           | Signature      | Description                       | Example               |
| ------------------- | -------------- | --------------------------------- | --------------------- |
| **`Function<T,R>`** | `T -> R`       | Transforms input to output.       | `String::length`      |
| **`Predicate<T>`**  | `T -> boolean` | Tests a condition.                | `s -> s.isEmpty()`    |
| **`Consumer<T>`**   | `T -> void`    | Performs an action (side-effect). | `System.out::println` |
| **`Supplier<T>`**   | `() -> T`      | Provides a value.                 | `Math::random`        |

### **2.3 Specialized Operators**

These are specializations of `Function`:

- **`UnaryOperator<T>`**: `T -> T` (Input and output are same type).
- **`BinaryOperator<T>`**: `(T, T) -> T` (Combines two of same type).

### **2.4 Handling Primitives (Performance)**

Standard generics (`Function<Integer, Integer>`) cause **autoboxing** overhead. Use primitive variants for hot paths:

- `IntPredicate`, `LongFunction`, `DoubleConsumer`, `IntToDoubleFunction`.
- **Rule:** If dealing with `int`, `long`, or `double` loops, always prefer the primitive interface.

## **3. Lambdas & Method References**

### **3.1 Lambda Syntax**

- **Standard:** `(x, y) -> x + y`
- **No Args:** `() -> 42`
- **Explicit Types:** `(int x) -> x + 1` (Useful if inference fails).
- **Block:** `x -> { log(x); return x + 1; }` (Requires explicit `return`).

### **3.2 Method References**

Use these when a lambda just calls an existing method.

| Type                     | Syntax           | Example Lambda Equiv      |
| ------------------------ | ---------------- | ------------------------- |
| **Static**               | `Math::max`      | `(a,b) -> Math.max(a,b)`  |
| **Instance (Arbitrary)** | `String::length` | `s -> s.length()`         |
| **Instance (Specific)**  | `myList::add`    | `e -> myList.add(e)`      |
| **Constructor**          | `ArrayList::new` | `() -> new ArrayList<>()` |

### **3.3 Ambiguity & Target Typing**

If a method is overloaded with different functional interfaces, the compiler may get confused.

```java
// Ambiguous if execute accepts both Runnable and Callable
// execute(() -> System.out.println("Hi")); // Compile Error

// Fix: Cast it
execute((Runnable) () -> System.out.println("Hi"));

```

## **4. Scoping and Variables (The Tricky Parts)**

### **4.1 "Effectively Final"**

Lambdas capture variables from the enclosing scope.

- **Local Variables:** Must be effectively final (assigned once).
- **Instance Fields:** Lambdas can read/write fields of the class freely (but beware of thread safety).

```java
int local = 10;
// local++; // Error: makes 'local' not effectively final
Runnable r = () -> System.out.println(local);

```

### **4.2 Lambda vs. Anonymous Inner Class (`this`)**

This is a key interview distinction.

- **Anonymous Class:** `this` refers to the _anonymous class instance itself_.
- **Lambda:** `this` refers to the _enclosing class_. Lambdas do not introduce a new level of scoping.

## **5. Composition & Helpers**

### **5.1 Chaining Functions**

- **`andThen(g)`**: Run `this` then `g`.
- **`compose(g)`**: Run `g` then `this`.
- **`Function.identity()`**: Returns the input as is.

```java
Function<String, String> trim = String::trim;
Function<String, String> upper = String::toUpperCase;
Function<String, String> pipeline = trim.andThen(upper);

```

### **5.2 Predicate Logic**

Combine small, readable units instead of writing complex boolean logic.

```java
Predicate<String> isValid = notNull.and(notEmpty).or(isAdmin);

```

### **5.3 Comparators**

Fluent sorting API:

```java
Comparator<Person> cmp = Comparator.comparing(Person::lastName)
    .thenComparingInt(Person::age)
    .reversed();

```

## **6. Advanced & Custom Functional Patterns**

### **6.1 Handling Checked Exceptions**

Functional interfaces do not allow checked exceptions. You must wrap them.

```java
// Utility to uncheck exceptions
static <T, R> Function<T, R> uncheck(ThrowingFunction<T, R> f) {
    return x -> {
        try { return f.apply(x); }
        catch (Exception e) { throw new RuntimeException(e); }
    };
}
// Usage
stream.map(uncheck(name -> Files.readString(Path.of(name))));

```

### **6.2 Missing Interfaces (TriFunction)**

Java stops at `Bi` (2 args). If you need 3, define it yourself:

```java
@FunctionalInterface
interface TriFunction<T, U, V, R> {
    R apply(T t, U u, V v);
}

```

### **6.3 Memoization**

Cache results of expensive pure functions.

```java
static <T,R> Function<T,R> memo(Function<T,R> f) {
    Map<T,R> cache = new ConcurrentHashMap<>();
    return x -> cache.computeIfAbsent(x, f);
}

```

## **7. Modern Java Integration (Java 16+)**

### **7.1 Records**

Records are immutable data carriers that work perfectly with streams.

```java
record User(String name, int age) {}

List<String> names = users.stream()
    .map(User::name) // Records generate accessors automatically
    .toList();

```

### **7.2 Serialization Warning**

Lambdas are technically serializable if the target type is `Serializable`, but **avoid this**. Lambda serialization is fragile across different JVM versions.

## **8. Functional Usage in Libraries**

### **8.1 Streams**

- **`map`**: 1-to-1 transformation.
- **`flatMap`**: 1-to-Many (flattens nested structures).
- **`mapMulti`** (Java 16+): Imperative version of flatMap (push-based).

### **8.2 Optional**

Use `Optional` as a functional container, not just a null check.

```java
// Bad
if (opt.isPresent()) return opt.get(); else return "default";

// Good
return opt.orElse("default");

// Lazy (Better for expensive defaults)
return opt.orElseGet(() -> complexCalculation());

```

### **8.3 Map Operations**

Declarative updates using functional arguments.

```java
// Merging counts
map.merge(word, 1, Integer::sum);

// Computing if missing
map.computeIfAbsent(key, k -> loadFromDb(k));

```

### **8.4 Concurrency**

Pass lambdas to Executors.

```java
ExecutorService pool = Executors.newFixedThreadPool(2);
pool.submit(() -> processData()); // Callable/Runnable

```

## **9. Quick Reference Cheat Sheet**

### **9.1 Interface Choice Guide**

- Need to return a boolean? → **Predicate**
- Need to create an object from nothing? → **Supplier**
- Need to transform X to Y? → **Function**
- Need to do something with X but return nothing? → **Consumer**
- Need to transform X to X? → **UnaryOperator**

### **9.2 Code Readability Rules**

1. **Prefer Method References:** `String::isEmpty` is clearer than `s -> s.isEmpty()`.
2. **Extract Complex Lambdas:** If a lambda is >3 lines, move it to a named method.
3. **Avoid Side Effects:** In `Stream.peek` or `map`, avoid modifying external state.
