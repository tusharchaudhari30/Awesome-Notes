# 2. Language Fundamentals

## 2.1 Variables and Mutability

```rust
let x = 5;          // immutable binding — the default
let mut y = 10;     // mutable binding — must be explicit
y += 1;

const MAX_USERS: u32 = 100_000;   // compile-time constant; type REQUIRED; SCREAMING_SNAKE_CASE
static APP_NAME: &str = "notes";  // one fixed memory location for the whole program
```

| | `let` | `const` | `static` |
|---|---|---|---|
| Mutability | opt-in with `mut` | never | only via `unsafe` or interior mutability (e.g. `Mutex`, atomics) |
| Type annotation | optional (inferred) | required | required |
| Evaluated | runtime | compile time (inlined at each use site) | compile time (single address) |
| Scope | block | any | global lifetime (`'static`) |

**Immutability by default** is a deliberate design decision: most bindings never need to change, and making mutation explicit means a reader can scan for `mut` to find all state that moves.

### Shadowing

```rust
let spaces = "   ";           // &str
let spaces = spaces.len();    // usize — SAME NAME, new variable, new type
```

Shadowing re-declares a new binding with the same name. Unlike `mut`, it can **change the type** and the result can itself be immutable. Idiomatic for parse-and-replace pipelines (`let input = input.trim();`). Each shadow is a genuinely new variable; the old one is inaccessible from that point (but not dropped early).

## 2.2 Scalar Types

| Category | Types | Notes |
|---|---|---|
| Signed ints | `i8 i16 i32 i64 i128 isize` | `i32` is the default for integer literals |
| Unsigned ints | `u8 u16 u32 u64 u128 usize` | `usize` = pointer width; required for indexing |
| Floats | `f32 f64` | `f64` default; IEEE-754; **no `Ord`, only `PartialOrd`** because `NaN != NaN` |
| Boolean | `bool` | one byte; only `true`/`false` — no truthy/falsy coercion, ever |
| Character | `char` | **4 bytes**, a Unicode scalar value — `'é'`, `'🦀'` are single chars |

```rust
let million = 1_000_000;      // underscores for readability
let hex = 0xFF; let oct = 0o77; let bin = 0b1010; let byte = b'A'; // u8
let typed = 57u8;             // suffix form
let f = 2.0f32;

// Conversions are ALWAYS explicit — no implicit numeric widening like Java/C
let a: i32 = 100;
let b: i64 = a as i64;             // `as` cast: truncates/wraps silently on narrowing!
let c: i64 = i64::from(a);         // From: only exists for lossless conversions
let d: u8  = u8::try_from(a).unwrap(); // TryFrom: fallible, returns Result — prefer for narrowing
```

**Overflow semantics (classic interview question):** debug builds panic on overflow; release builds wrap (two's complement). Explicit alternatives: `checked_add` → `Option`, `wrapping_add`, `saturating_add`, `overflowing_add` → `(value, bool)`.

## 2.3 Compound Types

### Tuples

```rust
let tup: (i32, f64, char) = (500, 6.4, 'x');
let (a, b, c) = tup;        // destructuring
let first = tup.0;          // index access
let unit = ();              // the "unit" type — what expressions with no value return
```

Fixed length, heterogeneous types. Tuples with more than 3 elements are a code smell — use a struct with named fields.

### Arrays and the first taste of slices

```rust
let arr: [i32; 5] = [1, 2, 3, 4, 5];   // length is PART OF THE TYPE
let zeros = [0; 8];                    // [0,0,0,0,0,0,0,0]
let slice: &[i32] = &arr[1..3];        // borrow a view: [2, 3]
```

- Arrays live on the **stack**, length fixed at compile time. For growable data use `Vec<T>` (chapter 5).
- Indexing is **bounds-checked**: `arr[10]` panics at runtime rather than reading garbage memory. `arr.get(10)` returns `Option<&i32>` for non-panicking access.

## 2.4 Functions

```rust
fn add(a: i32, b: i32) -> i32 {
    a + b                     // last expression WITHOUT semicolon = return value
}

fn early(n: i32) -> i32 {
    if n < 0 { return 0; }    // `return` for early exits only
    n * 2
}
```

- Parameter types and return types are **always explicit** — inference works inside function bodies, never across signatures. This is deliberate: signatures are contracts.
- Naming: `snake_case` for functions/variables, `CamelCase` for types/traits, `SCREAMING_SNAKE_CASE` for constants.
- No function overloading, no default arguments, no variadic user functions. Alternatives: different names (`new` / `with_capacity`), the builder pattern, `Option<T>` parameters, or generics with `impl Into<T>`.

## 2.5 Expressions vs Statements — Rust's Load-Bearing Distinction

Almost everything in Rust is an **expression** (produces a value): blocks, `if`, `match`, `loop`, function calls. Statements (produce nothing): `let` bindings, item declarations, and any expression followed by `;`.

```rust
let y = {                    // a block is an expression
    let x = 3;
    x + 1                    // no semicolon → block evaluates to 4
};                           // adding `;` after x + 1 would make the block yield ()

let level = if score > 90 { "high" } else { "low" };   // if is an expression — Rust's "ternary"
```

**The semicolon rule:** `;` turns an expression into a statement, discarding its value (yielding `()`). The infamous `mismatched types: expected i32, found ()` error usually means a stray semicolon on a function's last line.

## 2.6 Control Flow

### if / else if

```rust
if n % 4 == 0 { /* ... */ } else if n % 3 == 0 { /* ... */ } else { /* ... */ }
```

Conditions must be exactly `bool` — `if n {}` where `n: i32` is a compile error. No parentheses required around conditions; braces always required.

### Loops

```rust
// 1. loop — infinite, and an EXPRESSION: `break` can return a value
let result = loop {
    counter += 1;
    if counter == 10 { break counter * 2; }   // result = 20
};

// 2. while
while n > 0 { n -= 1; }

// 3. for — iterate anything implementing IntoIterator; the idiomatic default
for x in [10, 20, 30] { println!("{x}"); }
for i in 0..5 { }          // range: 0,1,2,3,4  (..= for inclusive end)
for (i, v) in vec.iter().enumerate() { }   // index + value

// Labeled breaks for nested loops
'outer: for x in 0..10 {
    for y in 0..10 {
        if x * y > 25 { break 'outer; }
    }
}
```

There is no C-style `for(init; cond; step)` — ranges and iterators cover it and optimize identically. Prefer `for x in &collection` over index arithmetic: it's clearer and eliminates bounds-check overhead.

`while let` loops as long as a pattern matches:

```rust
while let Some(item) = stack.pop() {
    println!("{item}");
}
```

## 2.7 Type Inference and Annotations

Rust infers types within a function body using all available evidence — including how a value is used *later*:

```rust
let mut v = Vec::new();   // type unknown here...
v.push(42);               // ...now inferred as Vec<i32>

let parsed: i32 = "42".parse().unwrap();       // annotation drives parse()
let parsed = "42".parse::<i32>().unwrap();     // or the "turbofish" ::<>
```

The **turbofish** `::<Type>` supplies generic arguments explicitly when inference has no anchor — most commonly with `.parse()`, `.collect()`, and `.into()`.

## 2.8 Comments and Documentation

```rust
// Line comment
/* Block comment */

/// Doc comment for the FOLLOWING item — supports Markdown, rendered by `cargo doc`.
///
/// # Examples
/// ```
/// assert_eq!(my_crate::add(2, 2), 4);
/// ```
pub fn add(a: i32, b: i32) -> i32 { a + b }

//! Doc comment for the ENCLOSING item — put at the top of lib.rs / a module file.
```

Code blocks inside `///` docs are **compiled and executed by `cargo test`** (doc-tests) — documentation examples can never silently rot. This is one of Rust's best cultural features; use it.
