# 4. Structs Enums and Pattern Matching

> Rust's data modeling story: structs are "AND" types (this field AND that field), enums are "OR" types (this variant OR that variant), and `match` makes handling every case compiler-enforced. Together they enable the signature Rust idiom: **make illegal states unrepresentable**.

## 4.1 Structs

```rust
struct User {
    username: String,
    email: String,
    active: bool,
    login_count: u64,
}

let mut u = User {
    email: String::from("a@b.com"),
    username: String::from("ana"),
    active: true,
    login_count: 1,
};
u.login_count += 1;      // mutability is all-or-nothing: the whole binding is mut, or none of it
```

You cannot mark individual fields `mut` — if the binding is `mut`, all fields are mutable; if not, none are. (Per-field interior mutability exists via `Cell`/`RefCell`, chapter 10.)

### Field init shorthand and struct update syntax

```rust
fn new_user(username: String, email: String) -> User {
    User { username, email, active: true, login_count: 0 }   // shorthand: field = variable name
}

let u2 = User {
    email: String::from("new@b.com"),
    ..u                    // take remaining fields from u — MOVES non-Copy fields!
};
// u.username is now moved; u as a whole unusable (u.email still accessible)
```

`..base` is not a copy: non-`Copy` fields are *moved* out of `base`. With `#[derive(Clone)]` you can write `..u.clone()` to keep both.

### Tuple structs and unit structs

```rust
struct Point(i32, i32);            // tuple struct: named type, anonymous fields
struct Meters(f64);                // NEWTYPE pattern: zero-cost type-safe wrapper
struct Marker;                     // unit struct: no data — useful as a trait-impl target

let m = Meters(5.0);
let raw: f64 = m.0;
```

The **newtype pattern** (`struct Meters(f64)`) is idiomatic Rust: `Meters` and `Seconds` are incompatible types even though both wrap `f64`, so the compiler catches unit mix-ups. Zero runtime cost.

## 4.2 Methods and Associated Functions

```rust
impl User {
    // Associated function (no self) — the conventional constructor
    fn new(username: String, email: String) -> Self {
        Self { username, email, active: true, login_count: 0 }
    }

    fn email_domain(&self) -> &str { self.email.split('@').nth(1).unwrap_or("") }  // read
    fn record_login(&mut self) { self.login_count += 1; }                          // mutate
    fn into_username(self) -> String { self.username }                             // consume
}

let mut u = User::new("ana".into(), "a@b.com".into());   // :: for associated functions
u.record_login();                                        // .  for methods
```

- `&self`, `&mut self`, `self` are shorthand for `self: &Self` etc. — the ownership decision table from chapter 3 applies directly.
- **Auto-ref/deref:** Rust inserts `&`, `&mut`, or `*` automatically on method calls — `u.record_login()` works without writing `(&mut u).record_login()`. This is why Rust needs no `->` operator.
- Multiple `impl` blocks per type are allowed (commonly used to group trait impls vs inherent methods).
- Methods consuming `self` enable *typestate* and builder patterns (chapter 15): `builder.build()` takes the builder by value so it can't be reused.

## 4.3 Enums — Sum Types with Payloads

Rust enums are far beyond C/Java enums: **each variant can carry its own data**.

```rust
enum Message {
    Quit,                          // no data
    Move { x: i32, y: i32 },       // named fields (like a struct)
    Write(String),                 // single payload
    ChangeColor(u8, u8, u8),       // tuple payload
}

impl Message {                     // enums have methods too
    fn describe(&self) -> String {
        match self {
            Message::Quit => "quit".into(),
            Message::Move { x, y } => format!("move to ({x},{y})"),
            Message::Write(s) => format!("write {s}"),
            Message::ChangeColor(r, g, b) => format!("color #{r:02x}{g:02x}{b:02x}"),
        }
    }
}
```

Memory: an enum is a **tagged union** — a discriminant plus space for the largest variant. The compiler heavily optimizes layout (e.g. `Option<&T>` is pointer-sized: the null bit-pattern encodes `None` — the "niche optimization").

### Modeling with enums: make illegal states unrepresentable

```rust
// ❌ stringly/flag-typed: allows nonsense states (connected=true AND error=Some)
struct Conn { connected: bool, error: Option<String>, retry_at: Option<u64> }

// ✅ each state carries exactly the data valid for it
enum Conn {
    Disconnected,
    Connecting { attempt: u32 },
    Connected { session_id: String },
    Failed { error: String, retry_at: u64 },
}
```

If a state combination shouldn't exist, design the types so it *can't* — then `match` forces every consumer to handle each legal state.

## 4.4 Option — Rust Has No Null

```rust
enum Option<T> { Some(T), None }     // in std, imported everywhere by default
```

Where other languages use `null` (and get `NullPointerException`), Rust uses `Option<T>`. The type system forces you to acknowledge absence before touching the value — `Option<String>` and `String` are different types and won't compile interchangeably.

```rust
let found: Option<&str> = Some("value");

// Extracting — from blunt to elegant:
let v = found.unwrap();                   // panics on None — tests/prototypes only
let v = found.expect("value must exist"); // panic with message — better
let v = found.unwrap_or("default");
let v = found.unwrap_or_else(|| compute_default());   // lazy default

if let Some(v) = found { /* use v */ }

// Combinators — the idiomatic style:
let len: Option<usize> = found.map(|s| s.len());
let n: Option<i32> = found.and_then(|s| s.parse().ok());   // flatMap
let ok = found.is_some();
let first_char: Option<char> = found.and_then(|s| s.chars().next());
```

`?` also works on `Option` inside functions returning `Option` (returns `None` early). Full error-handling story: chapter 6.

## 4.5 `match` — Exhaustive Pattern Matching

```rust
fn value_in_cents(coin: Coin) -> u8 {
    match coin {
        Coin::Penny => 1,
        Coin::Nickel => 5,
        Coin::Dime => 10,
        Coin::Quarter(state) => { println!("from {state:?}"); 25 }
    }
}
```

Three properties make `match` central:

1. **Exhaustive** — the compiler errors if any possible value is unhandled. Add an enum variant next year and every `match` that misses it fails to compile: refactoring safety net.
2. **An expression** — arms return values; the whole `match` evaluates to one.
3. **Binds payloads** — patterns destructure variant data in place.

```rust
match n {
    0 => "zero",
    1 | 2 => "one or two",            // OR patterns
    3..=9 => "a few",                 // inclusive range
    x if x < 0 => "negative",         // match guard (arbitrary condition)
    _ => "many",                      // catch-all (must be last)
}
```

**Style warning:** a careless `_ => ...` arm throws away exhaustiveness checking. When matching your own enums, prefer listing variants explicitly so future additions are caught.

## 4.6 The Pattern Language (works in `match`, `let`, `if let`, function params, `for`)

```rust
let Point { x, y } = p;                          // struct destructuring
let Point { x, .. } = p;                         // ignore the rest
let (a, _, c) = triple;                          // tuple, ignore middle
let [first, .., last] = arr;                     // array/slice ends
let Some(Ok(n)) = result_opt else { return };    // nested patterns

match slice {
    [] => "empty",
    [one] => "one element",
    [first, rest @ ..] => "first + rest bound to `rest`",
}

// Bindings with @: capture AND test
match n {
    small @ 1..=9 => println!("small number {small}"),
    _ => {}
}
```

### Binding modes: `ref`, `&`, and match ergonomics

Matching on a *reference* to data automatically binds by reference ("match ergonomics"):

```rust
let opt: &Option<String> = &Some("hi".to_string());
match opt {
    Some(s) => println!("{s}"),   // s: &String automatically — no move out of borrowed data
    None => {}
}
```

You rarely need explicit `ref`/`ref mut` in modern Rust — matching through `&`/`&mut` does the right thing.

## 4.7 `if let`, `let else`, `matches!`

```rust
// if let — when you care about ONE pattern
if let Some(user) = maybe_user {
    greet(&user);
} else {
    prompt_login();
}

// let-else — refutable pattern or bail; keeps the happy path unindented (Rust 1.65+)
let Some(user) = maybe_user else {
    return Err("not logged in".into());
};
greet(&user);            // user available in the OUTER scope

// matches! — pattern test as a bool
let is_active = matches!(status, Status::Active | Status::Trial { .. });
```

**Choosing:** `match` for multiple meaningful cases · `if let` for one case + optional fallback · `let else` for extract-or-early-return · `matches!` for boolean checks.

## 4.8 Deriving Common Behavior

```rust
#[derive(Debug, Clone, PartialEq, Eq, Hash, Default)]
struct Config { name: String, retries: u32 }
```

| Derive | Gives you |
|---|---|
| `Debug` | `{:?}` formatting — derive on nearly everything |
| `Clone` / `Copy` | explicit / implicit duplication (ch. 3) |
| `PartialEq` / `Eq` | `==`; `Eq` marks full equivalence (floats can't) |
| `PartialOrd` / `Ord` | comparisons, sorting, use in `BTreeMap` |
| `Hash` | usable as `HashMap`/`HashSet` key |
| `Default` | `Config::default()`; combine with `..Default::default()` |

These work because of traits — the subject of chapter 7.
