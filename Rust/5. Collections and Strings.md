# 5. Collections and Strings

## 5.1 Vec\<T\> — The Workhorse

A growable, heap-allocated, contiguous array. Your default collection.

```rust
let mut v: Vec<i32> = Vec::new();
let mut v = vec![1, 2, 3];                 // macro literal
let mut v = Vec::with_capacity(1000);      // pre-allocate when size is known — avoids reallocs

v.push(4);
let last: Option<i32> = v.pop();
v.insert(0, 99);           // O(n) — shifts everything right
v.remove(0);               // O(n) — shifts left
v.swap_remove(0);          // O(1) — swaps in the LAST element; order not preserved
v.extend([7, 8, 9]);
v.retain(|&x| x % 2 == 0); // in-place filter
v.sort();                  // stable sort; v.sort_unstable() is faster
v.sort_by_key(|u| u.age);
v.dedup();                 // remove CONSECUTIVE duplicates (sort first for global dedup)
v.truncate(2); v.clear();
let n = v.len(); let empty = v.is_empty();
```

### Access: panic vs Option

```rust
let third = v[2];              // panics if out of bounds
let third = v.get(2);          // Option<&i32> — use when index is untrusted
let first = v.first(); let last = v.last();
```

### Growth and memory

- Layout: `(ptr, len, capacity)` on the stack, elements on the heap.
- When `len == capacity`, pushing reallocates (roughly doubling) and **moves the buffer** — this is why you can't hold a reference to an element across a `push` (the borrow checker stops you; in C++ this is a classic dangling-iterator bug).
- Amortized `push` is O(1). `shrink_to_fit()` releases excess capacity.

### Iterating (full story in chapter 9)

```rust
for x in &v { }            // borrow: x is &i32; v usable afterwards
for x in &mut v { *x += 1; }
for x in v { }             // consume: x is i32; v is GONE afterwards
```

## 5.2 String and &str — The Topic Everyone Trips On

| | `String` | `&str` |
|---|---|---|
| What | owned, growable heap buffer | borrowed view (fat pointer: ptr + len) |
| Analogy | `Vec<u8>` | `&[u8]` |
| Mutation | yes (`push_str`, etc.) | no |
| Where literals live | — | `&'static str`, baked into the binary |
| Function params | avoid `&String` | **prefer `&str`** |

Both are **guaranteed valid UTF-8** (a `String` is literally a `Vec<u8>` with that invariant). Raw bytes belong in `Vec<u8>`/`&[u8]`; OS paths in `PathBuf`/`&Path`; C interop in `CString`.

### Creating and converting

```rust
let s: String = String::from("hello");
let s: String = "hello".to_string();       // equivalent
let s: String = "hello".to_owned();        // equivalent, most explicit about the cost
let view: &str = &s;                       // String → &str: free (deref coercion)
let owned: String = view.to_string();      // &str → String: allocates
let joined = format!("{a}-{b}");           // build without manual pushing
```

### Building and combining

```rust
let mut s = String::new();
s.push('x');                 // one char
s.push_str("yz");            // a &str

let a = String::from("foo");
let b = String::from("bar");
let c = a + &b;              // `+` MOVES a (consumed), borrows b. Quirky — prefer format!
let c = format!("{a}{b}");   // clearer, doesn't consume (but re-allocates)

let csv = ["a", "b", "c"].join(",");       // "a,b,c"
```

### Why you cannot index a String (interview classic)

```rust
let s = String::from("नमस्ते");
// s[0]  ❌ compile error
```

UTF-8 is variable-width (1–4 bytes per scalar). `s[i]` can't return "the i-th character" in O(1) because character boundaries aren't at fixed offsets — and "character" itself is ambiguous:

```rust
"नमस्ते".len()                    // 18 — BYTES, not characters
"नमस्ते".chars().count()          // 6  — Unicode scalar values
// grapheme clusters ("user-perceived characters") — needs the unicode-segmentation crate: 4
```

Slicing by byte range is allowed but **panics if it splits a UTF-8 sequence**: `&s[0..3]` is fine only on char boundaries (`s.char_indices()`, `s.get(0..3)` for the safe version).

### The everyday &str toolkit

```rust
s.trim(); s.trim_start(); s.trim_end();
s.to_lowercase(); s.to_uppercase();
s.contains("pat"); s.starts_with("h"); s.ends_with("!");
s.replace("old", "new");                    // returns a new String
s.find("pat")                               // Option<usize> (byte offset)
s.split(',')                                // iterator of &str
s.split_whitespace()
s.lines()
s.parse::<i32>()                            // Result<i32, _> — from the FromStr trait
s.chars().rev().collect::<String>()         // classic reverse-a-string
s.as_bytes()                                // &[u8]
```

`split` and friends return **iterators borrowing the original** — zero allocation until you `.collect()`.

## 5.3 HashMap\<K, V\>

```rust
use std::collections::HashMap;

let mut scores: HashMap<String, i32> = HashMap::new();
scores.insert("alice".to_string(), 10);     // insert MOVES owned keys/values in

let v: Option<&i32> = scores.get("alice");             // borrow lookup
let v: i32 = scores.get("alice").copied().unwrap_or(0);
scores.contains_key("bob");
scores.remove("alice");

for (k, v) in &scores { }        // arbitrary order! (randomized hasher)
```

### The entry API — idiomatic upsert (know this for interviews)

```rust
// Counter: the canonical example
let mut counts: HashMap<char, u32> = HashMap::new();
for c in text.chars() {
    *counts.entry(c).or_insert(0) += 1;
}

scores.entry("dave".into()).or_default();               // insert Default if absent
scores.entry("eve".into()).or_insert_with(expensive);   // lazy computation
scores.entry("al".into()).and_modify(|v| *v += 1).or_insert(1);
```

One hash lookup instead of the `contains_key` + `insert` double-lookup.

**Notes:**
- Keys need `Eq + Hash`. `f64` can't be a key (NaN breaks `Eq`).
- Default hasher (SipHash) is DoS-resistant but not the fastest — swap in `fxhash`/`ahash` for hot paths.
- Collect pairs directly: `let m: HashMap<_,_> = vec![("a",1),("b",2)].into_iter().collect();`

## 5.4 The Rest of std::collections

| Collection | Backing | Use when | Key ops |
|---|---|---|---|
| `Vec<T>` | growable array | default sequence | push/pop O(1)*, index O(1) |
| `VecDeque<T>` | ring buffer | queue / deque (BFS!) | push/pop both ends O(1) |
| `HashMap<K,V>` | hash table | default map | get/insert O(1)* |
| `BTreeMap<K,V>` | B-tree | sorted keys, range queries | O(log n), ordered iteration |
| `HashSet<T>` / `BTreeSet<T>` | as maps | uniqueness / sorted uniqueness | contains O(1)* / O(log n) |
| `BinaryHeap<T>` | max-heap | priority queue | push/pop O(log n), peek O(1) |
| `LinkedList<T>` | doubly linked | almost never — Vec/VecDeque beat it in practice | — |

```rust
use std::collections::{VecDeque, BTreeMap, HashSet, BinaryHeap};
use std::cmp::Reverse;

// Queue for BFS
let mut q = VecDeque::new();
q.push_back(start);
while let Some(node) = q.pop_front() { /* ... */ }

// Sorted map + range query
let mut events = BTreeMap::new();
events.insert(1700000000u64, "deploy");
for (ts, e) in events.range(1699990000..1700010000) { }

// Min-heap via Reverse
let mut heap = BinaryHeap::new();
heap.push(Reverse(5)); heap.push(Reverse(1));
let Reverse(smallest) = heap.pop().unwrap();   // 1

// Set algebra
let a: HashSet<i32> = [1,2,3].into();
let b: HashSet<i32> = [2,3,4].into();
let common: HashSet<_> = a.intersection(&b).copied().collect();
```

**Choosing:** start with `Vec` and `HashMap`. Reach for `BTreeMap` when you need ordering/ranges, `VecDeque` for FIFO, `BinaryHeap` for "always take the best next item". A sorted `Vec` + `binary_search` often beats `BTreeMap` for read-heavy data.

## 5.5 Ownership Interactions Cheat Sheet

```rust
// Borrowing an element pins the whole collection (can't push while borrowed)
let first = &v[0];
// v.push(4);                 // ❌ may reallocate → first would dangle
println!("{first}");
v.push(4);                    // ✅ after last use of the borrow

// Getting values OUT of a HashMap
let owned: Option<String> = map.remove("key");       // move out
let copy: Option<i32> = map.get("k").copied();       // Copy types
let cloned: Option<String> = map.get("k").cloned();  // Clone types

// Iterate + mutate values
for v in map.values_mut() { *v *= 2; }
```

**Interview-ready one-liner:** *"Vec and String are the same shape — (ptr, len, capacity) owning a heap buffer; &[T] and &str are the same shape — (ptr, len) borrowing one. All UTF-8 guarantees live in the String/&str pair."*
