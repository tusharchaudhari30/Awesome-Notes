# 13. Testing and Tooling

> Testing is built into the language and cargo — no framework to choose, no runner to install. `cargo test` runs unit tests, integration tests, and your documentation examples.

## 13.1 Unit Tests — Same File as the Code

```rust
pub fn add(a: i32, b: i32) -> i32 { a + b }
fn internal_helper(x: i32) -> i32 { x * 2 }     // private

#[cfg(test)]                       // compiled ONLY under `cargo test`
mod tests {
    use super::*;                  // pull in the parent module, private items included

    #[test]
    fn adds_positive() {
        assert_eq!(add(2, 2), 4);
    }

    #[test]
    fn helper_doubles() {
        assert_eq!(internal_helper(3), 6);   // ✅ unit tests CAN test private functions
    }

    #[test]
    #[should_panic(expected = "divide by zero")]
    fn div_zero_panics() { divide(1, 0); }

    #[test]
    fn parse_works() -> Result<(), String> {     // Result-returning tests: use ? freely
        let n: i32 = "42".parse().map_err(|e| format!("{e}"))?;
        assert_eq!(n, 42);
        Ok(())
    }

    #[test]
    #[ignore = "slow; run with cargo test -- --ignored"]
    fn expensive_scenario() { /* ... */ }
}
```

Assertion macros: `assert!(cond)`, `assert_eq!(a, b)`, `assert_ne!(a, b)` — all accept a trailing format message: `assert_eq!(got, want, "case {name} failed")`. On failure they print both values via `Debug` (so derive it). The `pretty_assertions` crate gives colored diffs for large structs.

## 13.2 Integration Tests — tests/ Directory

```
tests/
├── api_flow.rs        // each file compiles as its OWN crate
└── common/mod.rs      // shared helpers (subdirectory → not run as a test file)
```

```rust
// tests/api_flow.rs — sees your crate exactly like an external user:
use my_crate::{Client, Config};      // public API only

mod common;

#[test]
fn end_to_end_flow() {
    let client = common::test_client();
    assert!(client.ping().is_ok());
}
```

Unit tests verify internals; integration tests verify the public contract. Binary-only packages can't be integration-tested — hence the standard pattern: put logic in `lib.rs`, keep `main.rs` a thin wrapper.

## 13.3 Doc Tests — Documentation That Can't Rot

```rust
/// Adds two numbers.
///
/// # Examples
/// ```
/// assert_eq!(my_crate::add(2, 3), 5);
/// ```
///
/// ```should_panic
/// my_crate::divide(1, 0);
/// ```
pub fn add(a: i32, b: i32) -> i32 { a + b }
```

Every ` ``` ` block in `///` docs is compiled and run by `cargo test`. Hide setup lines from rendered docs with a leading `#`. Annotations: `no_run` (compile only), `ignore`, `should_panic`. For a library, doc tests double as your example suite — free coverage of exactly the code users will copy-paste.

## 13.4 Running Tests

```bash
cargo test                      # everything: unit + integration + doc
cargo test parse                # filter: any test with "parse" in its path
cargo test --lib / --doc        # just unit / just doc tests
cargo test --test api_flow      # one integration file
cargo test -- --ignored         # the #[ignore]d ones
cargo test -- --nocapture       # show println! from passing tests
cargo test -- --test-threads=1  # serialize (tests run in PARALLEL by default!)
```

**Parallel by default** matters: tests sharing files, ports, env vars, or a database will flake. Fix by isolating resources (tempdir per test, random ports) rather than serializing everything. `cargo nextest` (a drop-in runner) gives better isolation and output.

## 13.5 Test-Support Crates Worth Knowing

| Crate | Purpose |
|---|---|
| `pretty_assertions` | diff output for assert_eq |
| `proptest` / `quickcheck` | property-based testing (random inputs + shrinking) |
| `insta` | snapshot testing (`cargo insta review`) |
| `mockall` | mock trait implementations |
| `criterion` | statistical benchmarking on stable |
| `tempfile` | auto-cleaned temp dirs/files |
| `wiremock` / `httpmock` | HTTP server mocking for async clients |
| `tokio::test` | `#[tokio::test]` — async test functions |
| `trybuild` | assert that code FAILS to compile (macro/API authors) |

```rust
// Property test: parsing round-trips for ALL inputs, not just your 3 examples
proptest! {
    #[test]
    fn roundtrip(x: i64) {
        prop_assert_eq!(x.to_string().parse::<i64>().unwrap(), x);
    }
}

#[tokio::test]
async fn fetches() { assert!(client().ping().await.is_ok()); }
```

## 13.6 Clippy — The Lint Collection

```bash
cargo clippy                                  # 700+ lints beyond rustc's warnings
cargo clippy --all-targets -- -D warnings     # CI mode: warnings are errors
cargo clippy --fix                            # auto-apply machine-applicable fixes
```

Clippy teaches idiomatic Rust: it flags `if x == true`, manual `Option` matches that should be `map`/`unwrap_or`, `&String` parameters, redundant clones, `for i in 0..v.len()` index loops, and hundreds more — each with an explanation link.

```rust
#[allow(clippy::too_many_arguments)]          // targeted opt-outs where justified
fn legacy(...) {}
```

Lint levels can be set per-crate in `Cargo.toml` (`[lints.clippy]`). Useful groups: `clippy::pedantic` (opinionated, opt-in), `clippy::nursery` (experimental).

## 13.7 rustfmt — The End of Style Debates

```bash
cargo fmt                 # format everything, rust-standard style
cargo fmt --check         # CI: fail if anything is unformatted
```

Config via `rustfmt.toml` exists but the community norm is **defaults, untouched**. Format-on-save in your editor and never think about style again.

## 13.8 Benchmarking with Criterion

```rust
// benches/bench.rs  (+ [[bench]] harness = false in Cargo.toml)
use criterion::{black_box, criterion_group, criterion_main, Criterion};

fn bench_parse(c: &mut Criterion) {
    c.bench_function("parse_log_line", |b| {
        b.iter(|| parse(black_box(SAMPLE_LINE)))    // black_box: defeat constant-folding
    });
}
criterion_group!(benches, bench_parse);
criterion_main!(benches);
```

Criterion runs warmups, applies statistics, and reports regressions vs the previous run (`target/criterion/` keeps history + HTML plots). Always benchmark `--release`; never trust debug-build timings. For microbenchmarks on nightly there's `#[bench]`/`cargo bench` built in, but Criterion is the standard.

## 13.9 The Wider Toolbox

| Tool | What it does |
|---|---|
| `rust-analyzer` | the LSP — inline types, jump-to-def, inlay hints; non-negotiable |
| `cargo doc --open` | rendered API docs of your crate + all deps |
| `cargo tree -d` | find duplicate dependency versions |
| `cargo audit` | scan Cargo.lock against the RustSec vulnerability DB |
| `cargo deny` | licenses, bans, advisories policy in CI |
| `cargo outdated` | which deps have newer versions |
| `cargo expand` | show macro-expanded code (needs nightly) |
| `cargo flamegraph` | CPU profiling flame graphs |
| `cargo llvm-cov` / `tarpaulin` | code coverage |
| `cargo miri test` | run tests under Miri, the UB interpreter — the unsafe-code truth serum |
| `cargo watch -x check` | auto-rerun on file save (`cargo install cargo-watch`) |
| `sccache` | shared compilation cache across builds/machines |

### Debugging notes

`dbg!(expr)` prints file:line, the expression text, and its `Debug` value — and **returns the value**, so you can wrap it inline: `let y = dbg!(x * 2) + 1;`. Proper debuggers work fine (`lldb`/`gdb`, CodeLLDB in VS Code); in practice Rust developers lean on the type system, `dbg!`, and `tracing` more than steppers.

## 13.10 A Solid CI Recipe

```yaml
steps:
  - run: cargo fmt --check
  - run: cargo clippy --all-targets --all-features -- -D warnings
  - run: cargo test --all-features
  - run: cargo doc --no-deps          # docs must build; rustdoc catches broken links
  - run: cargo audit                  # optionally: cargo deny check
```

Cache `~/.cargo` and `target/` keyed on `Cargo.lock` (or use `Swatinem/rust-cache`) — cold Rust CI builds are slow; cached ones are fine.
