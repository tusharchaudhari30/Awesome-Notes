# 9. Closures and Iterators

> The functional heart of Rust. Iterator chains compile down to the same machine code as hand-written loops — the flagship demonstration of "zero-cost abstraction".

## 9.1 Closures

Anonymous functions that **capture their environment**:

```rust
let factor = 3;
let scale = |x| x * factor;            // types inferred; captures `factor`
let scale = |x: i32| -> i32 { x * factor };   // fully annotated form
println!("{}", scale(10));             // 30
```

### How captures work

The compiler chooses the *least invasive* capture that works, per variable:

1. **By shared reference** (`&T`) — closure only reads.
2. **By mutable reference** (`&mut T`) — closure mutates.
3. **By value / move** (`T`) — closure consumes, or you force it with `move`.

```rust
let list = vec![1, 2, 3];
let print = || println!("{list:?}");       // borrows list
print(); print();
println!("still mine: {list:?}");          // ✅

let mut count = 0;
let mut inc = || count += 1;               // mutably borrows count — closure binding needs `mut`
inc(); inc();
// println!("{count}");  ← would be an error BETWEEN inc() calls; fine after last one

let owned = vec![1, 2, 3];
let take = move || owned.len();            // `move` forces ownership transfer
// println!("{owned:?}");                  // ❌ owned moved into closure
```

`move` is required whenever the closure must **outlive the current scope** — spawned threads, async tasks, returned closures. Note: `move` + a `Copy` type copies; `move` + `Rc`/`Arc` moves the (cheap) handle — the standard trick for sharing into threads: clone the Arc, move the clone.

### The three closure traits

| Trait | Call signature | The closure… | Callable |
|---|---|---|---|
| `FnOnce` | `self` | consumes captures | once |
| `FnMut` | `&mut self` | mutates captures | many times, needs `mut` |
| `Fn` | `&self` | only reads captures | many times, anywhere |

Every closure implements `FnOnce`; non-consuming ones also implement `FnMut`; non-mutating ones also implement `Fn` (`Fn ⊂ FnMut ⊂ FnOnce`). The compiler infers the most capable set from the *body* (what it does with captures — `move` affects how values get in, not which trait).

```rust
fn apply<F: Fn(i32) -> i32>(f: F, x: i32) -> i32 { f(x) }        // accept a closure
fn make_adder(n: i32) -> impl Fn(i32) -> i32 { move |x| x + n }  // return one
let boxed: Box<dyn Fn(i32) -> i32> = Box::new(|x| x + 1);        // store heterogeneously
```

Accept the **most permissive** bound you can: take `FnOnce` if you call it once, `FnMut` if repeatedly, `Fn` only if you need shared calls. Plain `fn` function pointers coerce into all three.

## 9.2 The Iterator Trait

```rust
pub trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;   // the ONLY required method
    // ~75 default methods: map, filter, fold, … all built on next()
}
```

### Three ways to get an iterator from a collection

```rust
let v = vec![1, 2, 3];
v.iter()        // Iterator<Item = &i32>     — borrow
v.iter_mut()    // Iterator<Item = &mut i32> — mutate in place
v.into_iter()   // Iterator<Item = i32>      — consume the Vec
```

`for x in &v` desugars to `v.iter()`… `for x in v` to `v.into_iter()`. Pick by what you need to do with the items — and whether the collection should survive.

### Laziness (interview essential)

Adapters do **nothing** until a consumer runs the chain:

```rust
let it = v.iter().map(|x| { println!("side effect!"); x * 2 });   // prints NOTHING
let doubled: Vec<i32> = it.collect();                              // NOW it runs, once per item
```

The chain is a fused pipeline: each element flows through `map`→`filter`→… one at a time. No intermediate collections are built (unlike naive Java streams mental models or Python list comprehensions chained eagerly).

## 9.3 Adapters (lazy — return a new iterator)

```rust
v.iter().map(|x| x * 2)
 .filter(|x| x % 3 == 0)
 .filter_map(|s| s.parse::<i32>().ok())    // map + discard Nones in one step
 .take(5)  .skip(2)
 .take_while(|x| **x < 100)  .skip_while(...)
 .step_by(2)
 .enumerate()                              // (index, item)
 .zip(other.iter())                        // pair-wise; stops at shorter
 .chain(more.iter())                       // concatenate
 .rev()                                    // needs DoubleEndedIterator
 .flatten()                                // Iterator<Vec<T>> → Iterator<T>
 .flat_map(|x| x.children())               // map + flatten
 .peekable()                               // .peek() without consuming
 .inspect(|x| eprintln!("debug: {x:?}"))   // side-effect tap for debugging chains
 .cloned() / .copied()                     // &T → T
 .windows(3) / .chunks(3)                  // (on slices) overlapping / disjoint runs
```

## 9.4 Consumers (run the chain, produce a value)

```rust
.collect::<Vec<_>>()                       // into any FromIterator target — see below
.sum::<i32>()  .product::<i32>()
.count()
.min() .max() .min_by_key(|p| p.age) .max_by_key(...)
.fold(0, |acc, x| acc + x)                 // general reduction with initial value
.reduce(|a, b| a.max(b))                   // fold using first element as init → Option
.any(|x| x > 10)  .all(|x| x > 0)          // short-circuiting
.find(|x| x % 2 == 0)                      // first match → Option<Item>
.position(|x| x == 3)                      // index of first match → Option<usize>
.nth(4)  .last()
.for_each(|x| println!("{x}"))
.partition::<Vec<_>, _>(|x| x % 2 == 0)    // → (matching, rest)
.unzip()                                   // Iterator<(A,B)> → (Vec<A>, Vec<B>)
```

### collect — the shapeshifter

`collect()` builds *any* type implementing `FromIterator`; you choose with an annotation or turbofish:

```rust
let v: Vec<i32> = (1..=5).collect();
let s: String = chars.collect();
let set: HashSet<i32> = v.iter().copied().collect();
let map: HashMap<&str, i32> = pairs.into_iter().collect();
let nums: Result<Vec<i32>, _> = strs.iter().map(|s| s.parse()).collect();  // Result "flips outward"!
```

That last line is the killer feature: `Iterator<Result<T,E>>` collects into `Result<Vec<T>, E>` — first `Err` short-circuits the whole pipeline.

## 9.5 Implementing Your Own Iterator

```rust
struct Fib { a: u64, b: u64 }

impl Iterator for Fib {
    type Item = u64;
    fn next(&mut self) -> Option<u64> {
        let out = self.a;
        (self.a, self.b) = (self.b, self.a + self.b);
        Some(out)                                  // infinite iterator — None never returned
    }
}

let first10: Vec<u64> = Fib { a: 0, b: 1 }.take(10).collect();
```

Implement `next()` and you inherit the entire adapter/consumer library for free. Infinite iterators are fine — laziness plus `take` bounds them. Also useful: `std::iter::successors`, `std::iter::from_fn`, `once`, `repeat`, `empty` for building iterators without a named type.

## 9.6 Loops vs Iterators — Performance Truth

```rust
// These compile to equivalent (often identical) machine code:
let mut sum = 0;
for i in 0..v.len() { sum += v[i]; }      // may even be SLOWER: bounds check per index
let sum: i32 = v.iter().sum();             // no bounds checks; auto-vectorizes readily
```

Iterators are a **zero-cost abstraction**: adapters are structs that inline into a single loop under optimization. The iterator version often beats manual indexing because eliminating `v[i]` removes bounds checks and unlocks SIMD vectorization. Write the clear version; trust LLVM; profile before doubting.

## 9.7 Idiomatic Patterns

```rust
// Transform a collection (the bread-and-butter shape)
let names: Vec<String> = users.iter().map(|u| u.name.clone()).collect();

// Filter + transform owned data without cloning
let adults: Vec<User> = users.into_iter().filter(|u| u.age >= 18).collect();

// Word frequency in four lines
let mut freq = HashMap::new();
for w in text.split_whitespace() {
    *freq.entry(w).or_insert(0u32) += 1;
}

// Top-3 by score
let mut v: Vec<_> = players.iter().collect();
v.sort_by_key(|p| std::cmp::Reverse(p.score));
let top3 = &v[..3.min(v.len())];

// Sum of squares of even numbers — chain vs loop, same speed
let s: i64 = nums.iter().filter(|n| *n % 2 == 0).map(|n| n * n).sum();

// max on floats (no Ord): 
let m = xs.iter().copied().fold(f64::NEG_INFINITY, f64::max);
```

**Style guidance:** chains of 2–4 adapters read beautifully; beyond that, name intermediate steps or extract helper functions. If a chain needs mutable state shared across steps, a plain `for` loop is often clearer — Rust is multi-paradigm on purpose.
