# 15. Idioms Patterns and Performance

> What separates "Rust that compiles" from "Rust a senior reviewer approves": API design idioms, the patterns that replace OOP inheritance, and a performance checklist grounded in how Rust actually costs.

## 15.1 API Design Idioms

### Accept general, return concrete

```rust
fn process(data: &[u8]) { }              // not &Vec<u8>
fn greet(name: &str) { }                 // not &String
fn open(path: impl AsRef<Path>) { }      // accepts &str, String, PathBuf, &Path
fn set_name(&mut self, name: impl Into<String>) { self.name = name.into(); }  // caller passes &str or String
fn evens() -> impl Iterator<Item = u32> { (0..).step_by(2) }   // return iterators, let callers decide to collect
```

### Constructors and conversions

- `new()` for the obvious constructor; `with_x()` variants; `from_x()`/`try_from` for conversions. Implement `From`, never `Into` directly (Into is blanket-derived).
- Fallible construction returns `Result` — an invalid instance should be *unrepresentable*, not flagged.
- `Default` + struct update syntax for config-like types: `Config { port: 9000, ..Default::default() }`.

### The Builder pattern (Rust's answer to optional/named arguments)

```rust
#[derive(Default)]
pub struct ServerBuilder { port: Option<u16>, tls: bool, workers: Option<usize> }

impl ServerBuilder {
    pub fn port(mut self, p: u16) -> Self { self.port = Some(p); self }     // by-value chaining
    pub fn tls(mut self, on: bool) -> Self { self.tls = on; self }
    pub fn build(self) -> Result<Server, ConfigError> {                     // consumes builder
        Ok(Server { port: self.port.unwrap_or(8080), /* … */ })
    }
}
let server = ServerBuilder::default().port(9090).tls(true).build()?;
```

Ubiquitous in the ecosystem (`std::process::Command`, reqwest's `ClientBuilder`, clap). The `derive_builder`/`typed-builder` crates generate it.

### Newtype and typestate — making the compiler enforce your domain

```rust
// Newtype: incompatible IDs can't be swapped by accident; zero runtime cost
struct UserId(u64);
struct OrderId(u64);
fn cancel(user: UserId, order: OrderId) { }   // cancel(order_id, user_id) won't compile

// Typestate: operations only exist in valid states
struct Draft(Post);      struct Published(Post);
impl Draft     { fn publish(self) -> Published { Published(self.0) } }
impl Published { fn view(&self) -> &str { &self.0.body } }
// draft.view() is a COMPILE ERROR — the method doesn't exist on Draft
```

Both are instances of the core Rust design philosophy: **push invariants into types** so entire bug classes stop compiling.

### RAII guards

```rust
struct Timer { start: std::time::Instant, label: &'static str }
impl Drop for Timer {
    fn drop(&mut self) { eprintln!("{}: {:?}", self.label, self.start.elapsed()); }
}
let _t = Timer { start: std::time::Instant::now(), label: "parse" };   // logs on scope exit
// NOTE: `let _t`, not `let _` — `_` alone drops IMMEDIATELY
```

The pattern behind `MutexGuard`, transactions, temp files, spans in `tracing`.

## 15.2 Composition Over Inheritance

Rust has no inheritance. The replacements, in the order to try them:

| Instead of… | Use |
|---|---|
| Interface | trait (+ default methods) |
| Abstract base class with hooks | trait with default methods calling required ones |
| Subtype polymorphism in collections | `Vec<Box<dyn Trait>>` or an **enum of variants** |
| Reusing a base class's fields | composition: embed the struct, delegate methods |
| Method overriding | generics + trait bounds (static) or `dyn` (dynamic) |

```rust
// Enum-based polymorphism: closed set of variants — often better than dyn:
enum Shape { Circle { r: f64 }, Rect { w: f64, h: f64 } }
impl Shape {
    fn area(&self) -> f64 {
        match self {
            Shape::Circle { r } => std::f64::consts::PI * r * r,
            Shape::Rect { w, h } => w * h,
        }
    }
}
```

Enum dispatch is faster (a jump table, inlinable, no allocation), exhaustive-checked, but closed; `dyn Trait` is open for downstream extension. Choose by whether *users of your crate* need to add variants.

## 15.3 Everyday Idioms Checklist

```rust
// Combinators over match, when linear:
let name = user.map(|u| u.name).unwrap_or_else(|| "anon".into());

// let-else for extract-or-bail:
let Some(cfg) = load_config() else { return Err(Error::NoConfig) };

// Shadowing for staged transforms (avoids raw_x, parsed_x, valid_x naming):
let input = input.trim();
let input: u64 = input.parse()?;

// impl Display, get .to_string() free. Impl FromStr, get "x".parse() free.

// mem::take/replace to move out from behind &mut:
let batch = std::mem::take(&mut self.pending);

// Avoid index loops; if you need the index, .enumerate().
// Avoid .clone() inside hot loops; hoist or borrow.
// Iterator::collect::<Result<Vec<_>,_>>() to fail-fast a whole pipeline.
```

**Clippy is the style teacher** — run `cargo clippy` and read *why* each lint fires; it encodes most of this section.

## 15.4 How Rust Costs — A Mental Model

| Free (zero-cost) | Cheap | Watch out |
|---|---|---|
| generics/monomorphization | moves (memcpy of stack part) | `.clone()` of heap data in loops |
| iterator chains | `Arc::clone` (atomic increment) | allocation churn (String/Vec per item) |
| `Option<&T>`, newtypes | bounds checks (usually elided) | `dyn` calls in ultra-hot inner loops |
| lifetimes, borrows | `RefCell` borrow flag | locks held too long; false sharing |
| async state machines | enum dispatch | unbuffered file/network IO |

## 15.5 Performance Checklist (in order of typical payoff)

1. **`--release`.** Debug builds are 10–100× slower. Never benchmark debug.
2. **Measure first**: `cargo flamegraph`, `criterion`, `hyperfine` for CLIs. Guessing wastes weeks.
3. **Kill allocation churn:** preallocate (`Vec::with_capacity`, `String::with_capacity`); reuse buffers across loop iterations (`buf.clear()` instead of `String::new()`); build with iterators + `collect` (sizes hint automatically).
4. **Borrow, don't clone**, on hot paths — every `.clone()` of a `String`/`Vec` is a malloc + memcpy. `Cow` for the sometimes-modified case.
5. **Buffer your IO:** wrap `File`/sockets in `BufReader`/`BufWriter` — unbuffered per-byte syscalls are the classic 100× foot-gun. Lock stdout once (`let mut out = stdout().lock()`) for bulk printing.
6. **Pick the right structure:** `Vec` + `sort` + `binary_search` or a sorted merge often beats `HashMap`; `entry()` beats get+insert; `swap_remove` beats `remove` when order is irrelevant; `ahash`/`fxhash` beat SipHash for internal maps.
7. **Parallelize the easy wins:** `rayon::par_iter` on CPU-bound loops is often a one-line 4–8×.
8. **Cargo.toml knobs:** `lto = "fat"`, `codegen-units = 1`, `panic = "abort"` in `[profile.release]`; `RUSTFLAGS="-C target-cpu=native"` when you control the deployment hardware.
9. **Micro tier** (profile first!): `#[inline]` on tiny cross-crate hot functions; avoid bounds checks via iterators (not via `get_unchecked` unless proven and Miri-tested); `SmallVec`/`ArrayVec` for tiny usually-short vectors; struct-of-arrays layout for cache-bound number crunching.

## 15.6 Anti-Patterns to Unlearn

| Anti-pattern | Do instead |
|---|---|
| `.unwrap()` scattered through app code | `?` + `anyhow::Context`; `expect("reason")` where truly impossible |
| Fighting the borrow checker with `Rc<RefCell<_>>` everywhere | restructure ownership; pass `&mut` down; return values up |
| `Arc<Mutex<HashMap>>` as "the database" | channels + a single owner task, or a proper store (dashmap, sqlite) |
| Stringly-typed everything (`String` status fields) | enums — get exhaustive `match` for free |
| One 3000-line `main.rs` | lib + thin binary; modules per concern |
| Premature `dyn`/`Box` to "simplify types" | generics first; box only at genuine heterogeneity or compile-time pressure |
| Implementing `Deref` to simulate inheritance | composition + explicit delegation methods |
| `clone()` to silence every borrow error while learning | fine to start — but revisit; each one is a design question answered "copy it" |

## 15.7 Recommended Learning Path from Here

1. **The Rust Programming Language** ("the Book") — free at doc.rust-lang.org/book; these notes parallel it.
2. **Rustlings** — bite-size exercises, perfect borrow-checker gym.
3. **Rust by Example**, then **std docs** (read `Option`, `Iterator`, `Vec` pages fully — seriously).
4. **Effective Rust** (Drysdale) and **Rust for Rustaceans** (Gjengset) for the intermediate plateau.
5. Build: a CLI with clap → a REST service with axum + sqlx → something concurrent (job queue, chat server). The borrow checker clicks at project #2.
