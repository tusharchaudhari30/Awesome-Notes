# 1. Getting Started and Toolchain

## 1.1 What is Rust and Why It Exists

Rust is a systems programming language focused on three things at once — most languages force you to pick two:

| Goal | How Rust achieves it |
|---|---|
| **Memory safety** | Ownership + borrow checker verified at compile time — no garbage collector needed |
| **Performance** | Compiles to native code via LLVM; zero-cost abstractions; no runtime, no GC pauses |
| **Concurrency safety** | `Send`/`Sync` traits make data races a *compile-time* error ("fearless concurrency") |

**The core trade:** Rust moves the cost of memory and thread safety from *runtime* (GC pauses, segfaults, data races in production) to *compile time* (a stricter compiler and a steeper learning curve). Once a program compiles, whole categories of bugs are impossible:

- Use-after-free, double-free, dangling pointers
- Null pointer dereferences (there is no null — see `Option<T>`)
- Buffer overflows (bounds-checked indexing)
- Data races (enforced by `Send`/`Sync`)

**Where Rust is used:** operating systems (Linux kernel modules, Windows components), browsers (Firefox, Chrome components), infrastructure (AWS Firecracker, Cloudflare), CLIs (ripgrep, fd, bat), databases (TiKV, SurrealDB), blockchains, embedded systems, and WebAssembly.

**What Rust is *not*:** object-oriented in the classical sense (no inheritance), garbage-collected, or forgiving of vague designs. It rewards up-front thinking about who owns what data.

## 1.2 Installing the Toolchain: rustup

`rustup` is the official toolchain installer and version manager (analogous to `nvm`/`sdkman`):

```bash
# Install (Linux/macOS)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# Everyday commands
rustup update                 # update all installed toolchains
rustup show                   # what's installed & active
rustup default stable         # set default toolchain
rustup toolchain install nightly
rustup override set nightly   # use nightly for the current directory only
rustup component add clippy rustfmt rust-analyzer
rustup target add wasm32-unknown-unknown   # cross-compilation target
```

Installing gives you three tools:

| Tool | Role |
|---|---|
| `rustc` | The compiler. You rarely invoke it directly. |
| `cargo` | Build system + package manager + test runner + doc generator. Your daily driver. |
| `rustup` | Manages versions of the other two. |

**Release channels:**

- **stable** — new release every 6 weeks; what you should use. Backwards compatible.
- **beta** — next stable, for testing.
- **nightly** — daily builds with unstable features behind `#![feature(...)]` gates. Some tools (e.g. advanced `rustfmt` options, Miri) need it.

## 1.3 Cargo: The Center of the Universe

```bash
cargo new my_app              # new binary project (src/main.rs)
cargo new my_lib --lib        # new library project (src/lib.rs)
cargo build                   # debug build → target/debug/
cargo build --release         # optimized build → target/release/
cargo run                     # build + run
cargo run -- --port 8080      # pass args to your program (after --)
cargo check                   # type-check only, no codegen — much faster; use constantly
cargo test                    # run all tests
cargo doc --open              # build & open HTML docs for your crate + dependencies
cargo add serde --features derive    # add dependency to Cargo.toml
cargo remove serde
cargo update                  # update deps within semver ranges (rewrites Cargo.lock)
cargo clippy                  # lints (see chapter 13)
cargo fmt                     # auto-format
cargo tree                    # dependency tree — great for hunting duplicate versions
cargo install ripgrep         # install a binary crate globally (~/.cargo/bin)
```

**Development loop tip:** run `cargo check` (or let rust-analyzer do it) constantly while coding; only `cargo build`/`run` when you actually need the binary. Check skips code generation and is often 5–10× faster.

## 1.4 Anatomy of a Project

```
my_app/
├── Cargo.toml          # manifest: metadata + dependencies
├── Cargo.lock          # exact resolved versions (commit for apps; historically ignored for libs)
├── src/
│   ├── main.rs         # binary crate root  → fn main()
│   ├── lib.rs          # library crate root (optional; a package can have both)
│   └── bin/
│       └── extra.rs    # additional binaries: cargo run --bin extra
├── tests/              # integration tests (each file = separate crate)
├── benches/            # benchmarks
├── examples/           # runnable examples: cargo run --example foo
└── target/             # build output (never commit)
```

### Cargo.toml explained

```toml
[package]
name = "my_app"
version = "0.1.0"
edition = "2021"          # language edition (see 1.6)
rust-version = "1.70"     # minimum supported Rust version (MSRV)

[dependencies]
serde = { version = "1.0", features = ["derive"] }
tokio = { version = "1", features = ["full"] }
rand = "0.8"              # means ^0.8 → >=0.8.0, <0.9.0 (semver-compatible)

[dev-dependencies]        # only for tests/benches/examples
pretty_assertions = "1"

[build-dependencies]      # for build.rs build scripts
cc = "1"

[profile.release]
lto = true                # link-time optimization: smaller/faster, slower to build
codegen-units = 1         # better optimization, less build parallelism
panic = "abort"           # smaller binary; no unwinding
strip = true              # strip symbols
```

**Version syntax:** `"1.2.3"` means `^1.2.3` (any semver-compatible version). Other forms: `=1.2.3` (exact), `~1.2` (patch updates only), `>=1, <2`. For `0.x` versions, the *minor* number is treated as breaking: `0.8` will never resolve to `0.9`.

**Cargo.lock:** records the exact version of every transitive dependency, guaranteeing reproducible builds. Commit it for applications. For libraries the ecosystem historically ignored it (consumers resolve their own), though committing it is now acceptable practice too.

### Package vs Crate — precise vocabulary

- **Crate** — the unit of compilation; one library *or* one binary.
- **Package** — what `Cargo.toml` describes; contains **at most one library crate** and **any number of binary crates**.
- **crates.io** — the public registry where packages are published.

## 1.5 Hello World, Dissected

```rust
fn main() {
    println!("Hello, world!");
}
```

- `fn main()` — the entry point of a binary crate. Takes no arguments (CLI args come from `std::env::args()`); can return `()` or `Result<(), E>` (returning `Err` exits with code 1).
- `println!` — a **macro** (note the `!`), not a function. It must be a macro because it type-checks a variable number of arguments against the format string *at compile time*. A malformed format string is a compile error, not a runtime one.
- Formatting mini-language: `{}` uses the `Display` trait, `{:?}` uses `Debug`, `{:#?}` pretty-prints Debug, `{name}` captures a local variable directly (`println!("x = {x}")`), `{:>8}` pads, `{:.2}` sets precision, `{:x}` hex, `{:b}` binary.

## 1.6 Editions

Editions let Rust evolve syntax without breaking old code. Each crate declares its edition; crates on different editions link together seamlessly.

| Edition | Highlights |
|---|---|
| 2015 | Original release |
| 2018 | Non-lexical lifetimes, `async`/`await` groundwork, path/module simplification, `impl Trait` |
| 2021 | Disjoint closure captures, `IntoIterator` for arrays, reserved prefixes |
| 2024 | Refinements to temporaries/lifetimes, `unsafe` blocks required in `unsafe fn` bodies, async closures groundwork |

Migration is mechanical: `cargo fix --edition`, then bump `edition` in Cargo.toml. **Editions change surface syntax and defaults, never the core semantics or ABI** — this is how Rust does "major versions" without ecosystem splits.

## 1.7 Debug vs Release Builds

| Aspect | `cargo build` (dev) | `cargo build --release` |
|---|---|---|
| Optimization | `opt-level = 0` | `opt-level = 3` |
| Speed of resulting binary | Slow (often 10–100×) | Fast |
| Compile time | Fast | Slow |
| Debug assertions | On (`debug_assert!`, integer overflow **panics**) | Off (integer overflow **wraps**) |
| Debug symbols | Yes | No (unless configured) |

**Interview trap:** integer overflow panics in debug builds but wraps silently in release builds. To get explicit behavior in all builds use `wrapping_add`, `checked_add` (returns `Option`), `saturating_add`, or `overflowing_add`.

## 1.9 Mental Model Before You Dive In

Three ideas explain most of what makes Rust feel different; the next two chapters develop them fully:

1. **Every value has exactly one owner.** When the owner goes out of scope, the value is freed. No GC — freeing is deterministic and compiled in.
2. **You may lend a value out** — either many read-only references *or* one mutable reference, never both at once. The compiler enforces this.
3. **Types carry capability information.** Whether a type can be copied, sent across threads, or shared is expressed in traits (`Copy`, `Send`, `Sync`) and checked at compile time.

If you internalize "who owns this value, and who is borrowing it right now?", the borrow checker becomes a colleague instead of an adversary.
