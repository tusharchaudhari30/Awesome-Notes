# 10. Smart Pointers and Interior Mutability

> When single ownership and plain references aren't enough: heap indirection (`Box`), shared ownership (`Rc`/`Arc`), and mutation through shared handles (`Cell`/`RefCell`/`Mutex`). These are the escape hatches that keep Rust's rules — they just enforce some of them at runtime instead of compile time.

## 10.1 Decision Table (start here)

| Need | Single-threaded | Multi-threaded |
|---|---|---|
| Heap allocation / indirection | `Box<T>` | `Box<T>` |
| Shared ownership (many owners) | `Rc<T>` | `Arc<T>` |
| Mutate through a shared handle | `RefCell<T>` (or `Cell<T>` for Copy) | `Mutex<T>` / `RwLock<T>` / atomics |
| Shared + mutable together | `Rc<RefCell<T>>` | `Arc<Mutex<T>>` |
| Break a reference cycle | `Weak<T>` | `Weak<T>` (Arc's) |
| Borrow-or-own flexibility | `Cow<'a, T>` | `Cow<'a, T>` |

## 10.2 Box\<T\> — Simple Heap Allocation

```rust
let b = Box::new(5);            // 5 lives on the heap; b is the unique owner
println!("{}", *b);             // deref like a reference; freed when b drops
```

Three genuine reasons to use `Box`:

```rust
// 1. Recursive types — without indirection the size would be infinite
enum List {
    Cons(i32, Box<List>),       // Box = known pointer size → compiles
    Nil,
}
struct TreeNode { val: i32, left: Option<Box<TreeNode>>, right: Option<Box<TreeNode>> }

// 2. Trait objects — dyn Trait is unsized, needs a pointer
let handlers: Vec<Box<dyn Fn(&Request) -> Response>> = vec![];

// 3. Huge values — move a pointer instead of memcpying a large struct
let big = Box::new([0u8; 1_000_000]);
```

`Box` is a zero-overhead unique pointer (exactly `malloc`/`free` semantics, minus the bugs). `Option<Box<T>>` is still one pointer wide (niche optimization).

## 10.3 Deref and Drop — What Makes a "Smart" Pointer

```rust
use std::ops::Deref;

struct MyBox<T>(T);
impl<T> Deref for MyBox<T> {
    type Target = T;
    fn deref(&self) -> &T { &self.0 }
}
```

**Deref coercion:** where a `&U` is expected and you pass `&T` where `T: Deref<Target=U>`, the compiler inserts `.deref()` calls automatically — chained as needed. That's why `&String` flows into `&str` parameters, `&Vec<T>` into `&[T]`, `&Box<T>` into `&T`. Implement `Deref` only for genuine pointer-like wrappers (not to fake inheritance).

```rust
impl Drop for Connection {
    fn drop(&mut self) {           // destructor: runs deterministically at scope end
        self.flush();
        println!("connection closed");
    }
}
// drop order: variables in a scope drop in REVERSE declaration order; struct fields in order.
// force early: drop(conn);  — just moves it into a consuming fn
```

`Drop` is RAII for everything: files, sockets, locks, temp dirs. You cannot call `.drop()` manually (double-free risk) — use `std::mem::drop(value)`.

## 10.4 Rc\<T\> — Reference Counting (single-threaded)

```rust
use std::rc::Rc;

let a = Rc::new(String::from("shared"));
let b = Rc::clone(&a);            // increments refcount — cheap, no deep copy
let c = a.clone();                // same thing; Rc::clone spelling signals intent
println!("count = {}", Rc::strong_count(&a));   // 3
// value drops when the LAST Rc drops
```

- Use when ownership is genuinely shared and lifetimes can't express it: graph nodes, shared config, caches, interpreter environments.
- `Rc<T>` gives you **shared references only** — you can't get `&mut T` out of it while other handles exist (`Rc::get_mut` returns `Some` only at count 1). Mutation requires pairing with `RefCell` (below).
- **Not thread-safe** (non-atomic counter) — the compiler stops you from sending it across threads: `Rc<T>: !Send`.

## 10.5 Interior Mutability — Cell and RefCell

The borrow rules normally require `&mut` for mutation. **Interior mutability** types provide mutation through `&self`, keeping the aliasing-XOR-mutation invariant by other means:

### Cell\<T\> — for Copy types, zero overhead

```rust
use std::cell::Cell;
struct Counter { hits: Cell<u64> }
impl Counter {
    fn record(&self) { self.hits.set(self.hits.get() + 1); }   // &self, yet mutates!
}
```

`Cell` never hands out references to its contents — only `get` (copy out) and `set`/`replace` (move in). No aliasing possible → always safe, no runtime cost.

### RefCell\<T\> — borrow checking moved to runtime

```rust
use std::cell::RefCell;

let data = RefCell::new(vec![1, 2, 3]);
{
    let r1 = data.borrow();          // Ref<Vec<i32>>  — runtime shared-borrow count +1
    let r2 = data.borrow();          // ✅ many readers fine
}                                     // guards drop → counts released
data.borrow_mut().push(4);           // RefMut — exclusive

let a = data.borrow();
let b = data.borrow_mut();           // 💥 PANIC at runtime: already borrowed
```

Same rules as the compiler enforces — checked at runtime, violations **panic** (use `try_borrow`/`try_borrow_mut` for `Result` instead). Cost: a borrow-flag check per borrow.

**When legit:** mock objects recording calls through `&self` interfaces, memoization caches, graph algorithms — places where the code *is* correct but the static checker can't see it. If you're reaching for `RefCell` constantly, revisit the design.

### The classic combo: shared mutable state

```rust
use std::{rc::Rc, cell::RefCell};

let shared = Rc::new(RefCell::new(Vec::<String>::new()));
let handle = Rc::clone(&shared);
handle.borrow_mut().push("from handle".into());
println!("{:?}", shared.borrow());       // ["from handle"]
```

`Rc` = many owners; `RefCell` = mutation through any of them. The thread-safe twin is `Arc<Mutex<T>>` (chapter 11).

## 10.6 Weak\<T\> — Breaking Cycles

`Rc` leaks if handles form a cycle (counts never reach 0 — Rust prevents memory *unsafety*, not leaks). `Weak<T>` holds a non-owning reference:

```rust
use std::rc::{Rc, Weak};
use std::cell::RefCell;

struct Node {
    value: i32,
    parent: RefCell<Weak<Node>>,        // child → parent: weak (no ownership, no cycle)
    children: RefCell<Vec<Rc<Node>>>,   // parent → child: strong (owns)
}

let leaf = Rc::new(Node { value: 3, parent: RefCell::new(Weak::new()), children: RefCell::new(vec![]) });
let branch = Rc::new(Node { value: 5, parent: RefCell::new(Weak::new()), children: RefCell::new(vec![Rc::clone(&leaf)]) });
*leaf.parent.borrow_mut() = Rc::downgrade(&branch);

// Weak must be UPGRADED to use — returns None if the target was dropped:
if let Some(p) = leaf.parent.borrow().upgrade() { println!("parent = {}", p.value); }
```

Rule of thumb: ownership flows one direction with `Rc`/`Arc` (parent→child); back-edges (child→parent, cache entries, observers) are `Weak`.

## 10.7 Cow\<'a, T\> — Clone on Write

```rust
use std::borrow::Cow;

fn normalize(input: &str) -> Cow<'_, str> {
    if input.contains(' ') {
        Cow::Owned(input.replace(' ', "_"))    // allocate only when change needed
    } else {
        Cow::Borrowed(input)                   // zero-copy passthrough
    }
}
```

`Cow` (an enum: `Borrowed(&T)` | `Owned(T)`) defers allocation until mutation is actually required — ideal for "usually unchanged" transformation functions and deserializers.

## 10.8 Comparison Table

| Type | Ownership | Mutability | Checked | Thread-safe | Overhead |
|---|---|---|---|---|---|
| `Box<T>` | unique | via `&mut` | compile | as T | none |
| `Rc<T>` | shared | ❌ (alone) | compile | ❌ | refcount |
| `Arc<T>` | shared | ❌ (alone) | compile | ✅ | atomic refcount |
| `Cell<T>` | container | get/set only | — (can't alias) | ❌ | none |
| `RefCell<T>` | container | `borrow_mut()` | **runtime, panics** | ❌ | flag check |
| `Mutex<T>` | container | `lock()` | runtime, blocks | ✅ | lock |
| `Weak<T>` | none | — | `upgrade() → Option` | as Rc/Arc | refcount |

**Big picture:** these types don't bypass Rust's guarantees — they *relocate* enforcement. `RefCell` panics where the borrow checker would have errored; `Mutex` blocks where aliasing would have raced. Single owner (`Box`) → shared owners (`Rc/Arc`) → shared mutation (`+ RefCell/Mutex`): add machinery only as the problem demands it.
